# 서울시 뉴스레터 기반 네이버 블로그 자동화

**서울시 공식 뉴스레터를 확인하고, 기사 선정부터 원고·썸네일 제작과 네이버 블로그 발행 확인까지 Codex로 진행하는 작업 흐름입니다.**

## 구현 목적

뉴스레터에서 유용한 정보를 골라 블로그에 옮길 때는 기사 확인, 원고 작성, 이미지 제작, 편집기 서식 적용을 반복해야 합니다. 이 프로젝트는 그 과정을 작업 지침과 자동화 프롬프트로 정리하고, 중복 발행 방지와 발행 결과 확인 기준을 함께 마련했습니다.

독립 실행형 Python 프로그램이나 네이버 공식 발행 API 연동 서비스가 아닙니다. Codex의 브라우저 조작·이미지 생성 기능과 로그인된 네이버 계정을 이용합니다. 저장소를 내려받는 것만으로 자동 발행이 시작되지는 않습니다.

## 주요 기능과 작업 기준

- 한국시간 당일 뉴스레터의 날짜·호수·기사 내용을 확인합니다.
- 목록에 당일 호가 없으면 마지막 확인 번호 다음의 상세 페이지를 제한된 횟수만큼 확인합니다.
- 대표 기사와 독자에게 유용한 추가 기사 한 개를 선정하고 원문을 읽습니다.
- 제목 후보 5개를 비교하고, 본문에서 답할 수 있는 제목을 선택합니다.
- 글마다 원고와 가로 600px 썸네일을 준비합니다.
- 표, 소제목, 대표이미지, 카테고리, 태그를 확인한 뒤 발행합니다.
- 실제 게시글 주소와 본문을 확인하고 성공·부분 성공·실패·작업 생략을 구분합니다.
- 발행 기록을 대조해 이미 성공한 글을 다시 올리지 않도록 지시합니다.

위 항목은 AI가 따르는 작업 지침입니다. 프로그램으로 강제되는 검증이나 데이터베이스의 중복 차단 기능은 아닙니다.

## 사용 기술과 역할

| 구성 | 역할과 선택 이유 |
| --- | --- |
| Codex | 기사 조사, 원고 작성, 도구 실행을 하나의 작업 흐름으로 연결 |
| JavaScript · Codex CUA · Playwright 방식 API | Codex의 브라우저 도구를 통해 로그인된 네이버 편집기 입력·발행·공개 결과 확인 |
| 이미지 생성 도구 | 글 주제에 맞는 썸네일 제작 |
| Markdown | 사람이 읽고 수정할 수 있는 작업 기준과 실행 기록 관리 |
| JSON | 마지막으로 확인한 뉴스레터와 발행 결과를 파일로 보관 |
| Codex 반복 실행 | 평일 오전 9시 작업 시작에 사용한 예약 기능. 사용자 환경에서 별도 설정 필요 |

2026년 10월 20일 실행 기록에서 JavaScript로 `cua.createBrowserTab`, `cua.getBrowser` 및 `.playwright.` API를 호출한 것을 확인했습니다. 별도로 실행하는 Playwright 프로그램을 작성한 구조는 아니며, Codex가 작업 중 필요한 브라우저 명령을 실행합니다.

메일 검색에 사용했던 네이버 메일 MCP는 별도 구성입니다. 이 공개용 작업 흐름은 공식 뉴스레터 웹페이지를 기준으로 하므로 메일 계정 연결은 필수가 아닙니다.

## 파일 구조

```text
naver-blog-automation/
├── README.md
├── .gitignore
├── workflow.md                  # 공개용 작업 기준
├── automation-prompt.md         # 반복 실행에 사용할 프롬프트
└── examples/
    └── newsletter-state.example.json
```

실제 이메일, 계정 정보, 로그인 정보, 개인 실행 기록과 생성된 원고는 포함하지 않습니다. 기존 운영 폴더의 자료는 별도로 보존합니다.

## 준비 및 사용 방법

1. Codex에서 이 폴더를 열고 브라우저 조작과 이미지 생성 도구를 사용할 수 있는지 확인합니다.
2. 사용자가 브라우저에서 네이버에 직접 로그인합니다. 비밀번호를 문서나 채팅에 적지 않습니다.
3. 아래 명령으로 작업용 상태 파일을 만듭니다. 기존 파일이 있으면 복사하지 않습니다.

   ```powershell
   if (-not (Test-Path ./newsletter-state.json)) {
       Copy-Item ./examples/newsletter-state.example.json ./newsletter-state.json
   }
   ```

4. `automation-prompt.md`의 `<블로그 주소>`를 본인 주소로 바꾸고 사용할 카테고리를 확인합니다.
5. Codex에 `workflow.md`와 상태 파일을 읽고, 첫 실행은 원고·썸네일 준비까지만 진행하도록 요청합니다.
6. 결과를 확인한 후 공개 발행 범위를 직접 지정합니다. 반복 실행이 필요하면 평일 한국시간 오전 9시로 따로 등록합니다. 이 저장소에는 예약 설정 자체가 포함되어 있지 않습니다.

처음에는 공식 목록에서 실제 날짜와 내용을 확인한 뉴스레터를 기준으로 시작합니다. 예시 파일의 빈 값을 임의 번호로 채우지 않습니다. PC는 실행 중 켜져 있고 로그인·네트워크 연결이 유지되어야 합니다.

## 문제 해결 과정

| 문제 | 선택한 방법 | 결과와 남은 한계 |
| --- | --- | --- |
| 목록에 당일 뉴스레터가 보이지 않음 | 다음 상세 번호를 최대 5개 확인하고 실제 표시 날짜 판독 | 기존 기록에 상세 페이지에서 당일 호를 찾은 사례가 있음. 페이지 구조 변경과 접속 오류에는 대응 필요 |
| 발행 화면이 멈춰 재클릭할 위험 | 새 탭에서 게시 여부를 먼저 확인 | 중복 발행을 줄이기 위한 절차이며 시스템 차원의 차단은 아님 |
| 편집기와 공개 글의 서식 차이 | 공개 게시글에서 표 테두리·이미지 정렬·소제목 재확인 | 기존 실행 기록에 확인 결과가 남아 있음. 편집기 변경 시 재검증 필요 |
| 제목에 조건이 과도하게 나열됨 | 독자의 궁금증을 정리하고 후보 5개 비교 | 제목 작성 기준을 개선함. 검색 노출이나 방문자 증가 효과는 검증하지 않음 |

## 확인 범위와 현재 한계

- 기존 로컬 실행 기록에는 2026년 10월 16일·19일·20일 각각 두 글을 공개 발행하고 서식을 확인한 결과가 있습니다. 이번 공개 자료 정리에서는 해당 게시글을 다시 열어 검증하지 않았습니다.
- 공개용 문서와 예시는 기존 운영 지침을 정리한 것이며, 이 폴더로 처음부터 끝까지 새 발행 시험을 하지는 않았습니다.
- 로그인 만료, 추가 인증, 도구 사용 가능 여부, 웹페이지·편집기 구조에 따라 작업이 중단될 수 있습니다.
- 상태 파일과 실행 기록은 AI가 읽고 갱신합니다. 여러 작업을 동시에 실행할 때 중복을 막는 잠금 기능은 없습니다.
- 댓글 자동화는 별도 요구사항 문서만 있으며 이 프로젝트의 구현 기능에 포함하지 않습니다.
- 예약 실행의 현재 활성 상태와 PC 재부팅 후 자동 시작은 이번 정리에서 확인하지 않았습니다.
